## 三、1.0版本规划

### 3.1 设计愿景

> **3分钟一局、每局不一样、越打越强、停不下来**  
> 轻rogue × 装备驱动 × 像素地牢

### 3.2 核心改动优先级

```
P0 — 必做（无此不可发布）
├── 技能变异系统（每局BD差异化）
├── 装备词缀+6槽位（装备驱动深度）
├── Boss多阶段机制（战斗体验质变）
├── 房间制地图（策略性+探索感）
├── 元进度系统（跨局永久成长）
│
P1 — 应做（显著提升体验）
├── 随机事件房（rogue趣味性）
├── 成就系统（长期目标）
├── 每日挑战（回访动力）
├── 连击系统深化（操作反馈）
├── 音效+背景音乐（沉浸感）
│
P2 — 可做（锦上添花）
├── 排行榜（社交竞争）
├── 自定义操控布局
├── 宠物系统
├── 皮肤/外观
└── 小剧场/剧情
```

## 四、P0 系统详细设计

### 4.1 技能变异系统

**痛点**：当前每局体验完全相同 — 同样的3个技能、同样的升级路线。

**参考**：弓箭传说的"技能进化"、哈迪斯的"神明祝福"。

#### 设计

| 概念 | 说明 |
|------|------|
| **基础技能** | 每职业3个，开局自带（不变） |
| **变异** | 升级时，除了现有11种属性强化，新增"技能变异"选项 |
| **变异池** | 每个技能有3-4种变异，每局随机抽取2种可解锁 |
| **变异叠加** | 同一变异可叠加（如"火球+分裂"×2 = 3发火球） |

#### 变异示例

**战士 — 旋风斩**
| 变异名 | 效果 | 叠加 |
|--------|------|------|
| 🔥 烈焰旋风 | 旋风留下火域(2s)，经过敌人持续受伤害 | +1s火域持续时间 |
| ⚡ 雷鸣斩 | 旋风有30%概率眩晕敌人1s | +10%概率 |
| 🌀 吸引旋风 | 旋风将范围内敌人拉向中心 | +0.5拉力 |

**法师 — 火球术**
| 变异名 | 效果 | 叠加 |
|--------|------|------|
| 💥 分裂火球 | 火球命中后分裂为2个小火球 | +1分裂数量 |
| ❄️ 冰火交融 | 火球爆炸后留下冰域，减速50% | +1s冰域持续 |
| ⛓️ 连锁闪电 | 火球命中后跳至最近敌人(最多2次) | +1次跳跃 |

**牧师 — 治疗术**
| 变异名 | 效果 | 叠加 |
|--------|------|------|
| 🛡️ 圣疗 | 治疗同时获得20%最大HP护盾(3s) | +10%护盾比例 |
| ☀️ 光环 | 治疗留下光环，范围内友方持续回复 | +1s光环持续 |
| ⚔️ 惩戒 | 治疗时对周围敌人造成治疗量50%伤害 | +25%伤害转化 |

#### 实现要点

- `UpgradeManager` 扩展：新增 `SkillMutation` 升级类型
- 变异数据定义在 `CharacterClass.cs` 的 `SkillData` 中
- 每局开局随机从变异池抽取可用变异（Rogue 感）
- 变异叠加由 `PlayerController` 的技能方法内判断层数
- UI：升级选择时，变异选项用特殊边框(紫色/橙色)区分普通属性强化

### 4.2 装备系统深化

**痛点**：当前3个装备槽位太浅，装备仅提供基础属性，无刷装驱动力。

**参考**：暗黑不朽的"传奇装备改变技能"、流放之路的"词缀系统"。

#### 改动

| 改动 | 当前 | 目标 |
|------|------|------|
| **装备槽位** | 3(武器/护甲/饰品) | 6(武器/头盔/护甲/护腿/饰品×2) |
| **词缀系统** | ❌ 无 | ✅ 每件装备1-4条随机词缀 |
| **套装效果** | ❌ 无 | ✅ 2件套+4件套加成 |
| **装备品质** | 4级(白/蓝/紫/金) | 5级(+红色"远古"品质) |
| **词缀条数** | 0 | 白1条/蓝2条/紫3条/金4条/远古5条 |

#### 词缀池设计

**攻击类词缀**
| 词缀 | 范围 | 权重 |
|------|------|------|
| 攻击力 | +3~+15 | 常见 |
| 暴击率 | +2%~+8% | 常见 |
| 攻速 | +5%~+20% | 常见 |
| 暴击伤害 | +20%~+80% | 稀有 |
| 技能变异效果+1 | — | 极稀有(仅金色+) |

**防御类词缀**
| 词缀 | 范围 | 权重 |
|------|------|------|
| 生命值 | +10~+60 | 常见 |
| 防御力 | +2~+8 | 常见 |
| 生命回复 | +0.5~+3/s | 常见 |
| 受到伤害-5%~-15% | — | 稀有 |
| 闪避率 | +3%~+10% | 稀有 |

**特殊词缀（仅金色/远古）**
| 词缀 | 效果 |
|------|------|
| 🜏 旋风斩范围+30% | 改变技能形态 |
| 🜏 火球穿透+1 | 改变弹道行为 |
| 🜏 治疗连锁(治疗最近队友) | 新增机制 |
| 🜏 击杀回复3%最大HP | 续航质变 |
| 🜏 受击20%概率冰冻攻击者1s | 防御质变 |

#### 套装设计

| 套装名 | 2件套 | 4件套 | 适合职业 |
|--------|-------|-------|----------|
| 🔥 炎魔之怒 | 攻击+15% | 攻击有20%概率点燃(3s DOT) | 法师 |
| 🛡️ 不朽守护 | 防御+20% | 受到致命伤害时免死一次(60s CD) | 战士 |
| ✝️ 圣光祝福 | 生命回复+100% | 低于30%HP自动治疗50%最大HP(30s CD) | 牧师 |
| ⚡ 雷霆之怒 | 暴击+10% | 暴击时触发闪电链(3次) | 通用 |
| 🌀 虚空行者 | 移速+15% | 闪避CD-40% | 通用 |

#### 实现要点

- `Equipment.cs`：新增 `List<Affix> Affixes` 字段、`int SetId` 字段
- `Stats.cs`：新增 6 个装备槽位的 Bonus 字段，新增暴击伤害、闪避率等二级属性
- `EquipUI.cs`：从3槽位改为6槽位布局
- `ShopUI.cs`：显示词缀详情
- `Equipment.GenerateRandom()`：基于品质生成1-5条词缀
- 新增 `AffixPool` 静态类定义所有可能词缀
- 新增 `SetBonus` 静态类检查装备套装计数并应用加成

### 4.3 Boss 多阶段机制

**痛点**：当前Boss仅是Melee+Ranged+AOE拍地的加强版小怪，无阶段变化，战斗体验单调。

**参考**：哈迪斯的Boss双阶段、空洞骑士的Boss模式切换、艾尔登法环的Boss二阶段狂暴。

#### 设计原则

| 原则 | 说明 |
|------|------|
| **2阶段制** | 血量70%进入P2，AI/技能/外观变化 |
| **视觉提示** | P2转换时有咆哮动画+屏幕震动+颜色变化 |
| **新机制** | P2新增1-2种攻击模式，而非单纯数值提升 |
| **可学习** | 每种攻击有明确前摇，玩家可学习规避 |

#### 8关Boss设计

| 关卡 | Boss名 | P1机制 | P2机制(70%HP) |
|------|--------|--------|---------------|
| 1 森林 | 🌳 树精长老 | 缓慢追击+根须AOE(地面标记2s后出刺) | 召唤2个小树精+根须变3条 |
| 2 矿洞 | ⛏️ 矿洞巨魔 | 冲锋+范围锤击(有前摇) | 狂暴：冲锋变3连+锤击留裂缝(踩到受伤) |
| 3 冰谷 | ❄️ 冰霜女妖 | 冰锥弹幕(3方向)+冰冻圈 | 冰封自身(5s无敌回血)+散射冰锥×6 |
| 4 火殿 | 🔥 炎魔将军 | 火焰吐息(扇形)+地面火池 | 飞行模式(不可近战)+从天降火×3 |
| 5 墓穴 | 💀 亡灵领主 | 召唤骷髅兵+暗影弹 | 死亡凋零(全屏DOT，需击破4个灵魂柱中断) |
| 6 龙巢 | 🐉 远古幼龙 | 喷火(直线)+尾巴横扫 | 飞行+俯冲轰炸+地面龙息 |
| 7 虚空 | 🌀 虚空使者 | 传送+暗影分身(1个)+虚空弹 | 3个分身同时攻击+全屏虚空裂隙 |
| 8 魔王 | 👑 魔王·深渊 | 3连斩+暗影牢笼(困住玩家2s)+拍地AOE | 巨化+全屏暗黑波(需躲到柱后)+召唤4个精英 |

#### 实现要点

- `EnemyController.cs`：新增 `BossPhase` 枚举 + `bossPhase` 字段
- `Update()` 中检测HP比例，触发 `EnterPhase2()` 方法
- P2 AI 由新的 `UpdateBossPhase2()` 方法处理
- Boss视觉变化：`EnterPhase2()` 中修改 `SpriteRenderer.color`（红色加深）+播放VFX
- Boss血条：在 GameUI 中新增 Boss 专用大血条（屏幕顶部居中），含Boss名称
- 每关Boss在 `DungeonMapData` 中定义AI参数

### 4.4 房间制地图

**痛点**：当前为单房间无限刷怪，无探索感、无策略选择。

**参考**：哈迪斯的房间推进、杀戮尖塔的地图选择。

#### 设计

```
每局地图 = 5-8个房间，线性推进+分支选择

[S] = 起始房
[M] = 普通战斗房 (2-4波怪)
[E] = 精英战斗房 (1精英+小怪，奖励更好)
[?] = 事件房 (随机事件，见4.5)
[$] = 商店房 (可购买装备/恢复)
[B] = Boss房
[T] = 宝箱房 (免费装备/金币)

示例地图：
[S] → [M] → [M] → [E] → [?] → [M] → [B]
              ↘ [$] ↗         ↘ [T] ↗
```

#### 房间类型概率

| 房间类型 | 概率 | 内容 |
|----------|------|------|
| 普通战斗 | 40% | 2-3波怪，掉落金币 |
| 精英战斗 | 15% | 1精英+2波怪，必掉装备 |
| 事件房 | 20% | 随机事件(见4.5) |
| 商店房 | 10% | 出售3-4件装备+恢复药水 |
| 宝箱房 | 10% | 免费3选1装备/大量金币 |
| 休息房 | 5% | 回复30%HP+获得1个临时强化 |

#### 小地图UI

- 屏幕右上角显示当前进度：`房间3/7`
- 当前房间高亮，已通过房间灰显
- 下一房间选择（有分支时显示2条路线）

#### 实现要点

- 新增 `DungeonRun.cs` 类：管理当前一局的房间序列
- 新增 `RoomData.cs` 类：房间类型、敌人配置、事件ID
- `DungeonVisuals.cs`：每种房间类型有不同的装饰主题
- `GameManager.StartDungeon()` 改为从 `[S]` 房开始
- 击杀所有敌人后显示"继续"按钮，进入下一房间
- 小地图UI在 `GameUI.cs` 中添加

### 4.5 随机事件系统

**痛点**：当前刷怪-升级-刷怪的循环过于单调，缺少rogue核心的"意外性"。

#### 事件设计

| 事件名 | 描述 | 选择 | 结果 |
|--------|------|------|------|
| 🔮 神秘祭坛 | 古老的祭坛散发微光 | 献上鲜血 / 虔诚祈祷 | 失去20%HP，攻击+15% / 回复30%HP，防御+10% |
| 🧙 旅行商人 | 一个奇怪的商人拦住你 | 购买神秘药水 / 离开 | 花50金获得随机变异 / 无事发生 |
| 💀 诅咒宝箱 | 一个被黑雾环绕的宝箱 | 打开 / 离开 | 获得1件装备+永久debuff(移速-10%) / 无事发生 |
| 🏚️ 废弃营地 | 一堆散落的物资 | 搜索 / 休息 | 50%获得装备，50%遇怪 / 回复20%HP |
| 🎲 命运赌局 | 一个骰子悬浮在空中 | 赌一把 / 走开 | 50%获得大量金币(100-300)，50%失去30%HP / 无事发生 |
| 🗡️ 传奇之剑 | 一把插在石头中的剑 | 拔剑 / 留下 | 30%获得金色武器，70%受暗影伤害(-20%HP) / 无事发生 |
| 🌿 精灵之泉 | 清澈的泉水闪闪发光 | 饮用 / 装瓶 | 回复50%HP / 获得"精灵之水"道具(下次濒死自动回复30%) |
| 📜 古老卷轴 | 发黄的书卷上写满符文 | 阅读 / 焚烧 | 随机获得1个技能变异 / 获得30金币 |

#### 实现要点

- 新增 `RandomEvent.cs` 类：事件ID、描述文本、选项列表、结果列表
- 新增 `EventUI.cs`：事件卡片UI（标题+描述+选项按钮）
- `EventPool.cs`：静态类定义所有事件
- 房间制地图中 `?` 房间触发随机事件
- 事件结果通过 `Stats` 修改器或 `Equipment` 发放实现

### 4.6 元进度系统 (Meta Progression)

**痛点**：当前跨局成长仅有等级/金币存档，无"永久解锁"感。

**参考**：Dead Cells的"细胞解锁"、杀戮尖塔的"遗物池扩展"。

#### 设计

| 系统 | 说明 | 解锁货币 |
|------|------|----------|
| **灵魂之泉** | 每局结束获得"灵魂碎片"，在Hub的泉水中永久解锁 | 灵魂碎片 |
| **解锁内容** | 新变异加入升级池、新装备加入掉落池、新起始装备 | 灵魂碎片 |
| **灵魂等级** | 累计灵魂碎片提升等级，解锁更高级内容 | 累计碎片 |

#### 灵魂碎片获取

| 来源 | 数量 |
|------|------|
| 通关1关 | 10碎片 |
| 通关5关(1次运行全部通关) | 额外50碎片 |
| 击杀Boss | 5碎片 |
| 完成事件 | 2碎片 |
| 成就解锁 | 10-50碎片 |

#### 解锁树（部分）

```
🟢 灵魂等级1 (0碎片)
├── 基础变异池解锁 (0碎片，免费)
├── 商人起始金币+50 (5碎片)
└── 生命药水加入掉落池 (10碎片)

🔵 灵魂等级2 (50碎片累计)
├── 火焰变异池解锁 (15碎片)
├── 起始+10%攻击 (20碎片)
└── 稀有装备掉落率+5% (25碎片)

🟣 灵魂等级3 (150碎片累计)
├── 冰霜变异池解锁 (30碎片)
├── 套装装备加入掉落池 (35碎片)
└── 第4技能槽解锁 (50碎片) ← 终极目标

🟡 灵魂等级4 (400碎片累计)
├── 雷电变异池解锁 (40碎片)
├── 远古装备加入掉落池 (60碎片)
└── 自定义操控布局 (80碎片)
```

#### 实现要点

- 新增 `MetaProgression.cs` 类：管理灵魂碎片/解锁状态
- `PlayerPrefs` 存储所有解锁状态
- HubUI 中新增"灵魂之泉"入口按钮
- 新增 `SoulWellUI.cs`：解锁树UI
- 各系统（变异池、装备掉落池、起始加成）读取 `MetaProgression` 状态过滤可用内容

## 八、技术架构改进

### 8.1 当前技术债

| 问题 | 影响 | 解决方案 |
|------|------|----------|
| 全代码生成UI | 难维护、难迭代 | 考虑引入UI预制体+Addressables |
| 单文件过长 | GameManager.cs 700+行 | 拆分为GameManager+UIBuilder+CombatManager |
| 无数据驱动 | 硬编码数值散落各处 | 引入ScriptableObject配置 |
| 无对象池 | 频繁Instantiate/Destroy | 实现通用ObjectPool |
| 无音频系统 | 零音效 | 新增AudioManager |

### 8.2 代码重构计划

```
GameManager.cs (当前700+行) → 拆分为:
├── GameManager.cs       (~200行) — 游戏流程/状态机
├── UIBuilder.cs         (~300行) — UI构建逻辑
├── CombatManager.cs     (~150行) — 战斗/波次管理
└── NavButtonManager.cs  (~80行)  — 导航按钮管理
```

### 8.3 新增系统文件

```
Assets/Scripts/
├── Meta/
│   ├── MetaProgression.cs    — 元进度存档
│   ├── SoulWellUI.cs         — 灵魂之泉UI
│   └── AchievementManager.cs  — 成就系统
├── Room/
│   ├── DungeonRun.cs         — 房间序列生成
│   ├── RoomData.cs           — 房间数据定义
│   └── RoomMapUI.cs          — 小地图UI
├── Event/
│   ├── RandomEvent.cs        — 事件系统

│   └── EventUI.cs            — 事件交互UI
├── Equipment/
│   ├── AffixPool.cs          — 词缀池

│   └── EquipmentSlotExt.cs   — 6槽位扩展
```
