# 项目优化计划

日期：2026-06-02

## 验证总结

- `Tuanjie.exe -batchmode -projectPath D:\unity\demo -quit` 可以打开项目。
- `dotnet build Assembly-CSharp.csproj` 成功，错误数为 `0`。
- 生成警告是来自 Tuanjie/Codely 桥接引用的程序集版本冲突，不是游戏代码编译错误。
- 在 `Assets/Editor/CodexSmokeTest.cs` 中添加了批处理模式 Play 烟雾测试入口，但 Tuanjie 批处理模式没有可靠地完成 Play 循环。如需要，稍后从普通编辑器会话中使用它。

## P0 - 修复运行时入口和黑屏风险

这些应该首先完成，因为它们影响项目是否一致启动。

### 1. 对齐启动场景
- 当前构建设置仅包含 `Assets/Scenes/SampleScene.scene`。
- 上次编辑器场景设置指向 `Assets/Scenes/GameScene.scene`。
- 风险：编辑器播放和打包播放可能从不同的内容开始。
- 需要决策：选择一个官方入口场景。推荐：保留一个干净的 `Boot.scene` 或使 `SampleScene.scene` 成为唯一的官方启动场景。

### 2. 清理陈旧的场景对象
- `SampleScene.scene` 包含一个 `EnemySpawner` 对象，其脚本 GUID 在当前 `Assets/Scripts` 中不存在。
- `GameScene.scene` 包含旧版 `CharacterSlash` 玩家工作流程，而当前游戏流程在运行时创建 `PlayerController`。
- 推荐：删除陈旧的 `EnemySpawner`；在确认没有美术/参考价值后，存档或删除 `GameScene` 中的旧演示对象。

### 3. 停止每次重新构建 HUD
- `GameManager.BuildHUDElements()` 在运行时创建许多 UI 对象。
- 这与当前方向相冲突：创作 UI/预制件而不是代码生成的 UI/美术。
- 推荐：将 HUD、标题、中心、阶段选择、商店、技能树、装备 UI 逐个转换为预制件。Boss HP 已遵循这个方向。

### 4. 替换播放流程中的 `DestroyImmediate`
- `GameManager.StartDungeon()` 对 `DungeonVisuals` 使用 `DestroyImmediate`。
- 在播放模式下，使用 `Destroy` 和受控的重建生命周期。

## P1 - 代码架构清理

这些是主要的代码健康改变。

### 1. 拆分 `GameManager.cs`（目前约 1229 行）
- 仅保留高级流程入口。
- 将 UI 构造/绑定移到 `UIRoot` 或预制件控制器。
- 将波浪、生成、敌人杀死、副本完成逻辑移到 `CombatDirector`。
- 将副本视觉生命周期移到 `DungeonRuntime`。

### 2. 拆分 `PlayerController.cs`
- `PlayerInputController`：键盘、操纵杆、按钮。
- `PlayerMotor`：移动、冲刺、面向。
- `PlayerCombatController`：攻击、技能、冷却时间、伤害、治疗。
- `PlayerView`：精灵动画和本地 VFX 触发器。

### 3. 拆分 `EnemyController.cs`
- `EnemyState`：HP、攻击、防御、类型、奖励。
- `EnemyBrain`：近战/远程/精英/Boss AI。
- `EnemyCombat`：伤害、死亡、攻击执行。
- `EnemyView`：精灵、HP 条、打击闪光、死亡 VFX。

### 4. 将数据与运行时状态分离
- `Stats.cs` 应该变成 `PlayerRuntimeStats` 加上 `PlayerProgressData`。
- `Equipment.cs` 应该变成物品定义、库存状态和库存服务。
- 这也将使多人游戏转换容易得多。

## P2 - 性能优化

这些改进帧稳定性和移动设备性能。

### 1. 池化 VFX 对象
- `VFXHelper.cs` 为每次命中、技能、死亡、治疗和拖尾创建许多 `GameObject`。
- 用小对象池替换重复的 `new GameObject`/`Destroy`：粒子、伤害数字、斩击轨迹和脉冲。

### 2. 缓存生成的精灵/纹理
- `DungeonVisuals`、`TitleScreen`、`EnemyHealthBar`、`PlayerController` 和 `EnemyController` 重复创建 `Texture2D` 和 `Sprite`。
- 按键缓存单像素精灵和重复装饰精灵。

### 3. 减少每帧搜索调用
- `CameraFollow` 在目标为空时按标签搜索玩家。
- `EnemyController` 在目标为空时按标签搜索玩家。
- `GameManager` 在流程操作中使用 `FindObjectOfType` / `FindObjectsOfType`。
- 使用显式注册事件：玩家生成、敌人生成、敌人被杀、副本视觉创建。

### 4. 尽可能替换广泛的物理重叠扫描
- `PlayerController` 和投射物频繁使用 `Physics2D.OverlapCircleAll`。
- 使用非分配 API 或可重用碰撞体缓冲区进行近战/AOE 检查。

### 5. 将运行时视觉生成转换为资源
- 当前项目仍在代码中创建许多精灵/纹理。
- 新方向：创作精灵、预制件、粒子系统、材质。
- 按以下顺序转换：HUD -> 玩家/敌人预制件 -> 投射物/VFX -> 副本瓦片/装饰。

## P3 - 删除或存档未使用的代码

小心处理。在编辑器中确认每个项目后再删除。

### 1. `CharacterSlash.cs`
- 似乎属于旧的 `GameScene` 原型。
- 当前流程使用 `PlayerController` 和 `CharacterSprite`。
- 推荐：在确认不需要 `GameScene` 后，移动到 `Assets/Archive` 或删除。

### 2. `GameScene.scene`
- 包含旧的手工构建的角色工作流程。
- 推荐：存档为原型或从活动工作流程中删除。

### 3. `SampleScene.scene` 中的 `EnemySpawner` 对象
- 有缺失/未知的脚本 GUID。
- 推荐：从场景中删除对象。

### 4. 过多的包
- `visualscripting`、`timeline`、`collab-proxy`、多个 IDE 包和自适应性能可能未被使用。
- 推荐：仅在确认编辑器工具不依赖它们后才删除。从未使用的运行时包开始，而不是 IDE 包。

## 多人游戏准备

在 P0/P1 之前不要开始网络代码。首先使单人游戏架构对网络友好。

### 1. 权限分割
- CombatDirector 拥有波浪、生成、伤害、战利品、Boss、清除结果。
- 客户端仅显示状态并发送输入。

### 2. 状态对象
- 玩家状态、敌人状态、投射物状态、战利品状态、副本会话状态。
- 这些应该是可序列化的快照。

### 3. 确定性输入
- 用播种随机服务替换游戏结果内的直接 `Random.Range`，用于地图、战利品、敌人构成和升级选择。

### 4. UI 仅成为本地视图
- UI 不应该决定规则、奖励、敌人死亡、升级或战利品。

## 建议工作顺序

1. 创建一个官方启动场景并删除陈旧的 `EnemySpawner`。
2. 将主 HUD 从生成代码转换为预制件。
3. 将 `GameManager` 拆分为流程和战斗指挥官。
4. 池化 VFX 和投射物对象。
5. 拆分玩家输入/电机/战斗/视图。
6. 拆分敌人状态/大脑/战斗/视图。
7. 将核心数据转换为可序列化状态以实现多人游戏。
8. 为启动、职业选择、阶段开始、波浪清除、Boss 清除添加适当的 PlayMode 测试。
